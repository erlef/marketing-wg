# OTP 27/28 Release for TLS 1.2

Releases cover other CVE resolutions as detailed in [OTP Release 2026-11-24]({% post_url wg/cna/2026-11-24-otp-release %}).

This report covers one OTP CVE that specifically affects OTP 27/28:

- [CVE-2026-124286](https://cna.erlef.org/cves/CVE-2026-124286.html) - TLS 1.2 Client Completes Handshake Without a Server Certificate

# Available Versions

The following OTP releases resolve this CVE:

- [28.5.0.9](https://www.erlang.org/patches/OTP-28.5.0.9)
- [27.3.4.14](https://www.erlang.org/patches/OTP-27.3.4.14)

The recent versions of OTP 29 already fix this issue.

# Description

The best approach is to upgrade to 28.5.0.9, or 27.3.4.14 (or later, or to OTP 29). However, if you cannot immediately upgrade, take note of "Pre-upgrade mitigation" below.

### TLS 1.2 Client Completes Handshake Without a Server Certificate

[CVE-2026-124286](https://cna.erlef.org/cves/CVE-2026-124286.html)


**Who is affected:** Applications on OTP 27/28 prior to the fixed versions that make outgoing TLS or DTLS connections with `ssl:connect` and can negotiate TLS 1.2, which the default options allow. This includes libraries built on `ssl`, such as HTTP clients. TLS servers are not affected, and clients restricted to TLS 1.3 are not affected.

**Impact:** An attacker positioned between your client and the server can impersonate any server, then read and modify all data on the connection. The attacker simply sends no certificate, and the client accepts the handshake anyway. `{verify, verify_peer}`, certificate path validation, `verify_fun` and the hostname check all have no effect. `ssl:connect/3` returns `{ok, Socket}` as if the connection were secure.

**Pre-upgrade mitigation:** Restrict client connections to TLS 1.3 with `{versions, ['tlsv1.3']}`. If a client must use TLS 1.2, offer only the static RSA key exchange cipher suites (filter `ssl:cipher_suites(all, 'tlsv1.2')` with `ssl:filter_cipher_suites/2` on `key_exchange =:= rsa`). Those suites have no forward secrecy and many servers don't accept them.
